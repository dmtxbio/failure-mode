01 / PROVENANCE

Direct from the source

Letters are retrieved from the openFDA Complete Response Letters API. The API already supplies extracted text. Each record retains its source filename, retrieval timestamp, content hash, and original PDF link.

A complete response letter means FDA did not approve an application in its current form at that review. The dataset includes letters associated with both approved and unapproved applications. The status shown here is the FDA dataset’s status, not a verified current market status.

02 / INTERPRETATION

Evidence before inference

Review areas are assigned by versioned, deterministic text rules. They are candidate topic mentions, not expert-adjudicated deficiencies. Exact excerpts and their source letters let you inspect every match.

Routine letter language can mention a topic without identifying a deficiency. Rules suppress some standard boilerplate, but false positives and omissions remain. Unmatched letters remain searchable. No drug names, therapeutic areas, or approval probabilities are invented.

Planning questions are authored prompts. The corpus is selective, redacted, and incomplete; a checklist cannot cover every applicable requirement. An empty match is not evidence that a risk is absent.

04 / CONNECT YOUR TOOLS

Research from your assistant

The included MCP server exposes the archive to compatible assistants: search letters, retrieve source evidence, inspect corpus coverage, and generate planning prompts by stage.

search_letters(q="immunogenicity")
get_letter(letter_id="…")
get_corpus_stats()
get_planning_checklist(stage="Development")

Run the local MCP integration alongside this application. Setup instructions and an example client configuration are included in integrations/README.md.
